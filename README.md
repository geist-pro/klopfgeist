# Klopfgeist

Listen to a paper as an audiobook and review it by voice. Say "stop", speak your comment, say
"continue". The comments are transcribed, attached to the sentence you reacted to, and exported as
a review draft, as annotated text or as an annotated PDF.

Native apps for iPhone, iPad and Mac (`apple/`) and for Android (`android/`). Speech is recognized on
the device; nothing you say leaves it unless you turn on sync with your own server.

Site and downloads: <https://apps.geist.pro/klopfgeist/>

Klopfgeist is made by [GEIST](https://geist.pro), the Human-Centered Information Systems group at
TU Clausthal. Internal names still say "Margin Voice", the app's working title.

## What works

- Convert a PDF, Markdown, RTF or text file into a narrated book on the device, or import an
  audiobook (`.m4b`) with its text.
- Voice commands in English and German: stop, continue, cancel, back, again, bookmark, faster,
  slower. Headset and steering-wheel buttons do the same without a word.
- Comments are recorded, transcribed and anchored to the sentence that was playing. A first word
  such as "weakness" or "question" sorts a comment into the review draft.
- Export: Markdown with the comments after each sentence, a review draft sorted by tag, the PDF
  with highlights and notes, or the whole book as a `.drafttalk` package.
- Sync through a Nextcloud or other WebDAV folder (and iCloud Drive on Apple devices, once the build
  carries the entitlement, see `apple/project.yml`).
- A session trace records what the recognizer heard and what the app decided, so that a command
  that was not heard can be replayed in a test.

## Layout

| Path | What |
|---|---|
| `spec/vectors` | Language-neutral conformance cases. Both cores run them. |
| `apple/MarginVoiceKit` | Swift package: `MarginVoiceCore` (pure rules), `MarginVoiceSession` (the review session against ports), `MarginVoiceApple` (AVFoundation, Speech, MediaPlayer adapters). |
| `apple/App`, `apple/AppMac` | The iOS and macOS apps. The Xcode project is generated by XcodeGen from `apple/project.yml`. |
| `android/core`, `android/session` | Kotlin twins of the two pure Swift modules (JVM, no Android). |
| `android/app` | Compose app and the Android adapters (ExoPlayer, AudioRecord, Vosk, Media3). |
| `docs` | [Architecture](docs/ARCHITECTURE.md), device checklists, and what differs from the earlier apps. |

## Build

You need Xcode 26 with [XcodeGen](https://github.com/yonaskolb/XcodeGen) for the Apple apps, and the
Android SDK with JDK 17 or 21 for Android.

```sh
# Swift core and session (fast, no simulator)
cd apple/MarginVoiceKit && swift test

# iOS and macOS apps
cd apple && xcodegen
xcodebuild -scheme MarginVoice -destination 'generic/platform=iOS Simulator' \
  -skipPackagePluginValidation -skipMacroValidation build
xcodebuild -scheme MarginVoiceMac -destination 'platform=macOS' \
  -skipPackagePluginValidation -skipMacroValidation ARCHS=arm64 build

# Android
cd android && source tools/env.sh
tools/fetch_models.sh                 # once: the two Vosk command models (about 160 MB)
./gradlew :core:test :session:test    # seconds, no Android
./gradlew :app:testDebugUnitTest :app:assembleDebug
```

The Mac app is Apple silicon only (the Kokoro voice needs Float16). A signed Android release needs
`android/keystore.properties`; TestFlight uploads go through `scripts/testflight.sh`.

Some tests read an unpublished paper that is not in this repository and are skipped without it
(`android/core/src/test/resources/fixtures/README.md`).

## Testing voice commands on a real phone

`android/tools/voice_suite.py` lets a Mac speak every command phrase in several voices while a phone
next to it listens, and reads the verdict from the app's log:

```sh
cd android && tools/voice_suite.py --language en      # or de; --voices, --volumes, --only
```

It reports, per phrase and voice, whether the command fired, was not heard, or was heard as a
different command. See the top of the script for the set-up.
